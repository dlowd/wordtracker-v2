# Word Tracker audit

Audited Oct 31, 2026. This is a read-only review of `~/Projects/wordtracker-v2`. It covers the working tree, which includes another agent's edits in progress. Line numbers in `js/main.js` and `index.html` may shift as that work lands. If a number is off, search for the quoted code.

## Verdict

The core design is sound. Supabase stores per-day word deltas, totals come from summing them, the date math is DST-safe, and rewards are computed from totals. The weak spot is the signed-in write path. `main.js` swaps in Supabase versions of add, set and undo, and they return a different shape than the word-entry form expects. That breaks Undo, confuses Set total, and lets Set total work from a stale number. Save errors are also invisible, because the status line is commented out of `index.html`. Fix the items below and the app should hold up for November.

## Fix before Nov 1

### 1. Undo deletes saved entries without asking, and can't undo what you just typed

**Where:** `js/word-entry.js:63`, `js/word-entry.js:166-179`, `js/main.js:2241`, `js/main.js:2270`, `js/main.js:2273-2306`.

**What happens:**

- On page load, Undo is enabled whenever this device has cached entries.
- Each tap deletes the newest saved entry on the server. That entry can be from yesterday.
- There is no confirmation and no message. The button stays enabled, so each further tap deletes one more entry.
- After Mary adds words, Undo turns grey. It cannot undo a typo she just made.
- Same cause: after a successful Set total, the form thinks nothing changed (`js/word-entry.js:349-352`). It keeps the number in the box, and its cached total goes stale. Setting the total back to that stale value is then ignored as "unchanged".

**Why:** the Supabase overrides return `wordDataStore.getSnapshot()`, which is `{ total, entries }`. The form reads `result.entry`, which is always missing.

**Smallest fix:** make the three overrides return `{ total, entry }`.

- Add and set: `entry: { delta }`.
- Undo: select `id, entry_date, delta`. Ask `confirm("Remove 1,250 words logged Nov 3?")`. Return the deleted row as `entry`.

### 2. Failed saves are silent, and quick-add throws the number away

**Where:** `index.html:92-96` (status line commented out), `js/word-entry.js:320-323`, `js/word-entry.js:366-369`, `js/quick-add.js:226-230`, `js/main.js:1696`.

**What happens:** Mary's phone is offline, or Supabase returns an error.

- Inline form: the number stays in the box. No message appears.
- Quick-add mode: `processAddMode` catches the error and does not rethrow. The modal closes as if it saved, and clears the input. The words are not logged, and nothing tells her.

**Smallest fix:**

- Restore the status `<p>`. It is already styled small (`.word-entry__status`).
- Rethrow at the end of the catch blocks in `processAddMode` and `processSetMode`.
- Wrap the two `await` calls in `handleSubmit` (`js/word-entry.js:156-160`) in try/catch, so the inline form doesn't raise an unhandled rejection.

The quick-add modal then shows the error and keeps the number.

### 3. Set total uses a stale total after another device logs words

**Where:** `js/main.js:2244-2253`, `js/main.js:2194-2196`.

**What happens:** The phone tab has been open since morning and shows 10,000. Mary adds 1,000 on the laptop, so the server has 11,000. On the phone, without reloading, she sets the total to 12,000. The phone computes 12,000 − 10,000 = 2,000 and inserts that. The server total becomes 13,000.

The same happens if the refresh after an earlier save failed. `refreshEntriesFromSupabase` returns silently on error and leaves the old total in place.

**Smallest fix:** at the top of the `setTotal` override, `await refreshEntriesFromSupabase()`. Make that function return `false` on error, and throw in `setTotal` if it did, rather than guess. See also "Refresh when the app comes back" below.

### 4. Project settings say "Project updated." before the save finishes

**Where:** `js/settings-modal.js:236-237`, `js/main.js:1972-2004`.

**What happens:** When signed in, `handleProjectSave` returns a Promise. The modal reads `.message` off the Promise, finds nothing, and shows "Project updated." at once. If the save then fails, the message still says updated and the old dates stay. Mary uses this screen to check dates and goal on Nov 1.

**Smallest fix:** in the modal, `Promise.resolve(this.onProjectSubmit(payload)).then((fb) => this.showProjectFeedback(fb));`. In `handleProjectSave`, add a `.catch` that returns `{ success: false, message: 'Could not save project.' }`.

### 5. Supabase JS loads at runtime from esm.sh, unpinned

**Where:** `js/supabase-client.js:1`. The built bundle (`dist/assets/index-CLMHg-bP.js`) still imports `https://esm.sh/@supabase/supabase-js@2` at runtime.

**What happens:**

- `main.js` imports this module statically. If esm.sh is down or blocked, the whole module graph fails. The page stays blank, because `#app` starts `inert` and `#new-layout` starts `hidden`.
- `@2` floats. Any new 2.x release reaches Mary without a deploy.
- Third-party code runs with access to the session token in localStorage.

**Smallest fix:** install `@supabase/supabase-js` at an exact version and import it from the package, so Vite bundles it. A stopgap with no install is to pin the exact version in the URL.

### 6. The dev entry editor deletes days outside the project window

**Where:** `js/main.js:1817`, `js/main.js:1846-1858`, `index.html:395`.

**What happens:** The editor lists only the days from start date to end date. On save it deletes every entry in the project, then re-inserts only the listed days. Words logged on Oct 31 (prep) or Dec 1 are deleted without warning. The intro text says "Saving will append the necessary corrections", which is not what the code does. This editor is the only way to fix a past day, so Mary may well use it.

**Smallest fix:** in `populate()`, build the timeline from the project days plus every date that has entries (`dailyTotals.map((d) => d.date)`), deduplicated and sorted. Correct the intro text.

### 7. Supabase checks in the dashboard (not code)

- **Project is active.** `js/supabase-client.js:11` connects to a project that has been idle for a year. If it is on the free tier, it has likely paused. Restore it and test a sign-in today.
- **Row-level security is on for all three tables.** The anon key ships in the bundle. Sign-up is now open to anyone (`index.html:236`, "the link will set up your account"). RLS is the only barrier between a stranger's account and Mary's data. The policies the code needs are listed at the end.
- **The deploy origin is an allowed redirect.** Magic links use `emailRedirectTo: window.location.origin` (`js/main.js:2756`). If the new origin is not in Auth → URL Configuration, the link sends Mary to the old Site URL.
- **Take a backup.** Use Settings → Export data before Nov 1.

## Worth doing this month

### Refresh when the app comes back to the foreground

**Where:** `js/main.js:2638` (`registerDataListeners`). There is no `visibilitychange` or `focus` handler.

**Scenario:** Mary opens a phone tab left open since yesterday. It shows yesterday's total and yesterday's "Words today" until she saves something. That stale total also feeds item 3.

**Fix:** on `visibilitychange` to visible, if signed in, call `refreshEntriesFromSupabase()`. This also recomputes "today" after midnight.

### A moment offline at load looks like a sign-out

**Where:** `js/main.js:2631` ignores the `error` from `getSession()`.

**Scenario:** The access token expired overnight, and the phone has no signal when Mary opens the app. The token refresh fails, so `getSession` returns no session plus an error. The app treats that as signed out, clears the local cache, and shows "Sign in to continue". She may request magic links that can't help. It recovers on its own once online.

**Fix:** if `getSession` returns an error, call `toggleAuthUI(null)` and set the feedback text to "Can't reach the server. Check your connection." Do not call `applyAuthState(null)`, which wipes the cache and preferences.

### Signing out resets theme and stat choices on every device

**Where:** `js/main.js:2570-2582` (`clearUserData` writes default preferences with a fresh timestamp), `js/main.js:2405-2410` (newer local preferences win and get pushed to the server).

**Scenario:** Mary logs out on the laptop and back in. Her theme goes back to Classic and hidden stats reappear, on the phone too. The offline case above triggers the same reset.

**Fix:** at the end of `clearUserData`, run `updatePreferences((p) => ({ ...p, updatedAt: null }))`. The server copy then wins at the next sign-in.

### Don't await Supabase calls inside `onAuthStateChange`

**Where:** `js/main.js:2633-2635`.

**Scenario:** Supabase's docs warn that awaiting other Supabase calls inside this callback can deadlock. That path runs when a sign-in arrives while the page shows the sign-in screen. Example: the offline case above, followed by a successful token refresh. `loadUserData` then runs inside the callback and can hang.

**Fix:** `supabase.auth.onAuthStateChange((_e, session) => { setTimeout(() => applyAuthState(session?.user || null), 0); });`

### The hidden reward gallery downloads every unlocked photo on each load

**Where:** `js/rewards-gallery.js:119-121`, called through `js/main.js:1289-1292` on every metrics update.

**Scenario:** The gallery modal is hidden, but `<img>` tags are built for every unlocked reward, and browsers fetch them anyway. The current kitten set is 106 MB across 61 files, up to 9 MB each. By late November, a cold load on the phone pulls about 30 full-size photos.

**Fix:** set `img.loading = 'lazy'` before `src` (one line). The new reward images should also be resized; that work is with the other agent.

### "Words per day required" is inflated, worst at month end

**Where:** `js/stats.js:146-147`.

**Scenario:** It divides the remaining words by days left minus one.

- Day 1 shows 1,725 instead of 1,667.
- On Nov 29, exactly on pace with 3,333 left, the morning shows "Today: 0 / 3,333" instead of 1,667.
- The number then drops as she writes during the day.

**Fix:** base it on the total at the start of today: `ceil(max(goal − (totalWords − wordsToday), 0) / requirementDays)`. Keep `highlightToday` as is. This changes a number Mary saw last year, so check with her first.

### Mobile: input zoom and small buttons

**Where:** `css/word-entry.css:194-222` ("Compact Layout Overrides v2", applied at every width).

**Scenario:** The word-count input is 0.9rem (14.4 px). iOS Safari zooms the page when an input under 16 px gets focus, so every log starts with a zoom. Buttons are about 30 px tall, and Undo sits right under Update Words, which makes item 1 easier to trigger.

**Fix:** `font-size: 1rem` on `.form-field__input` and `.form-field__select`. Add `min-height: 44px` on `.button` under `max-width: 480px`.

### Primary button contrast in three themes

**Where:** `css/word-entry.css:99-103` puts white text on `--teal-600`. The theme values are in `css/themes.css`.

**Numbers:** Midnight 2.8:1, Sunset 3.6:1, Emerald 3.8:1. WCAG AA needs 4.5:1 for this text. Classic, Twilight and Wicked pass.

**Fix:** use `--teal-700` for the button in Emerald (5.5:1) and Sunset (5.2:1). In Midnight, use dark text (`#0f172a`, 6.4:1).

### Import can double the server totals

**Where:** `js/main.js:583-598`.

**Scenario:** The project upsert and the entries delete don't check `error`. If the delete fails, the insert still runs, and every day is counted twice.

**Fix:** destructure `{ error }` from both calls and throw before inserting.

### Log words for yesterday

**Where:** `js/main.js:2228` and `js/main.js:2257` always use today's date.

**Scenario:** Mary writes until 1 a.m. and logs then. The words land on the next day. The only way to move them is the dev editor (item 6).

**Fix:** add a "for yesterday" checkbox that passes a date key into the add and set overrides. Change Undo's ordering (`js/main.js:2283-2284`) to `created_at` first, so Undo still removes the latest entry made.

### The image preview dialog has no name

**Where:** `index.html:534-536`. The heading the dialog points to is commented out. `js/main.js:1165` tries to focus it, which does nothing.

**Fix:** restore the `<h2>`. It can be visually hidden.

- **Split and prune `main.js` (2,782 lines).** Tradeoff: a big diff with no visible gain, risky mid-month. The candidates are listed after this list.

## Supabase: what the code assumes

The database is not visible from the repo, so this lists what the code needs. Inserts into `entries` carry no `user_id`, and reads filter only by `project_id`. RLS on `entries` must therefore check ownership through `projects`.

| Table | Operations the code uses | Policy needed (USING and WITH CHECK) |
|---|---|---|
| `projects` | select, insert, upsert (update) | `user_id = auth.uid()` |
| `entries` | select, insert, delete | `project_id in (select id from projects where user_id = auth.uid())` |
| `preferences` | select, upsert, delete | `user_id = auth.uid()` |

Also assumed:

- `preferences.user_id` has a unique constraint. The upsert uses `onConflict: 'user_id'` (`js/main.js:2164`).
- `entries.created_at` defaults to `now()`. Undo and ordering depend on it (`js/main.js:2192`, `js/main.js:2284`).
- `projects.start_date` and `end_date` are `date` columns.
- Policies apply `to authenticated`. Nothing is granted to `anon`.

If RLS is off on `entries`, anyone with the public anon key can read or delete every user's word counts.
